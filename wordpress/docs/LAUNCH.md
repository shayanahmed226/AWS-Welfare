# Launch checklist — outstanding organization/hosting inputs

This package is installable and locally tested. It is **not a production launch**, a legal opinion, verified registration statement, bank-ownership check or proof of real payment settlement.

## Must supply/review before accepting real donations

- [ ] PHP/database WordPress hosting for awswelfareorg.com; confirm whether an existing site must be preserved or migrated. HTTPS, DNS and backup responsibility.
- [ ] Verified official logo file and organization name spelling. The current wordmark is temporary text. Do not use Amazon Web Services branding.
- [ ] Meezan account title, bank name, account number/IBAN, optional branch and approved QR, independently verified against society bank documents.
- [ ] Approved privacy, donation/refund and terms policies in both languages, effective/review dates, responsible contacts, retention periods, refund authority and handling rules. Starter drafts require organizational/legal review, not blind publication.
- [ ] Confirmed public email, phone, address and any official WhatsApp. No map is shown without a confirmed address; a map integration can be added only after privacy/accessibility review.
- [ ] Confirmed organization story, team/governance and registration evidence before claims are made.
- [ ] Reviewed live campaign descriptions, use of funds, real targets, locations, dates, Urdu copy and active/paused state.
- [ ] Approved, consent-appropriate organizational photographs. Current artwork/placeholders are explicitly not proof of project activity.
- [ ] Reviewed impact definitions, reporting periods, internal evidence references and authorized editors. No impact figures are seeded.
- [ ] Real approved reports/PDFs with reporting dates and verified summaries, and registration documents if available.
- [ ] Assistance safeguarding/review process, application retention periods, staff responsibilities and real volunteer opportunities (or retain the general-interest empty state).
- [ ] Approved team roles/photos, editorial posts, report types and consent-reviewed gallery images; remove all QA/sample content.
- [ ] Staff donation reconciliation/refund procedure and least-privilege accounts.
- [ ] Persistent nonpublic proof storage, upload limits, encryption/backups and tested staff-only download on the target host.
- [ ] Configured domain-authenticated email transport with controlled inbox delivery tests. Fix failed acknowledgment/notification status and test retry.
- [ ] Correct cache exclusions/language keys, host routing, security updates and protected backup/restore drill.
- [ ] Remove all local demos/test data. Do not move a QA database, synthetic bank details or QA accounts into production.
- [ ] Final organization review of English and Urdu content, keyboards/screen readers, 360/390px mobile screens, real phones and host-specific deployment checks.

## Optional or intentionally unavailable

- Online payment gateways, recurring donations and automated refunds: unavailable until approved merchant access, official documentation and tested server-side integration are supplied.
- Public donor lists, beneficiary identities, fabricated partner/testimonial/impact blocks and tax receipts: not provided.
- Performance scores or legal/WCAG certification: no unmeasured or unaudited promise.

Do not publish a live donation CTA connected to a host that cannot persist records or protect proofs. GitHub Pages remains suitable only for the older static prototype and package downloads, not the WordPress administration/payment workflow.
